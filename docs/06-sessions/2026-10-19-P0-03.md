### Answer 1 — ADR-014 (Product/Architecture owner)

> ADR-014: should the domain crate keep `serde` (derive only) as its single external dependency, with
> JSON and other formats staying in the pipeline and synth crates? Rejecting it means reworking P1-01's
> merged types into hand-written mirror types.
>
> - **Accept (Recommended)** — ADR-014 becomes Accepted. The domain types keep their serde derives and
>   the merged code stands as is.
> - **Reject** — ADR-014 becomes Rejected. A follow-up package must remove serde from the domain crate,
>   which the output contract's rule 1 then has to accommodate.

**Answer: "Accept (Recommended)".**

### Answer 2 — reviewer agents' Bash (Amendments row 11; Security/Release owner)

> Reviewer agents (amendment row 11): they have no Edit or Write tool but keep Bash, and
> `.claude/settings.json` auto-allows some writing commands such as `git commit` and `cargo fmt` for
> every agent. How should that be handled?

>   only read and search. They lose the ability to run tests or git diff themselves.
> - **Add deny rules** — Keep Bash for reviewers and add deny or ask rules for writing commands in
>   .claude/settings.json. This changes the permission profile for every agent and session.
> - **Accept the risk** — Keep things as merged. Reviewers stay read-only by instruction only.

**Answer: "Remove Bash (Recommended)".**

### Answer 3 — synchronous façade (Amendments row 20; Product/Architecture owner)

> Library API style (amendment row 20): the command and query trait methods are synchronous `fn`, and
> implementors from P1-02 run Tokio behind them. Keep that, or switch the traits to `async fn` before
> the first implementor exists?
>

>   own. Async work is hidden inside the implementations.
> - **Switch to async** — P1-02 changes the traits to async fn first. Callers, including the CLI, then
>   need an async runtime.

**Answer: "Keep synchronous (Recommended)".**
